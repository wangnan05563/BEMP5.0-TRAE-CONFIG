## 二、W8 全流程成功路径（最短可复现）

```
PreCheck + start-bemp-env.ps1 启动 5 服务（全UP）
  → 测试用例承接（bemp-test-common 统一索引）
  → 五段式回归（登录→导航[menu_path配置+叶子dump兜底]→注入→断言[响应/样式/console三通道]→清理落盘）
  → 缺陷双重定位（共享组件源码 ↔ 浏览器组件实例转储互相印证）
  → 最小侵入修复（不动共享框架组件，修复收敛在个性化文件）
  → 回归验证 → 报告落盘（round6_bugfix_regression_report.md + 截图）
```

## 三、适用场景与不适用场景

### 适用场景
- BEMP 票据系统银行个性化开发测试
- 需求驱动的功能测试（有明确PRD）
- Web 端到端测试（前端+后端+数据库）
- 多阶段流程化测试
- Vue2 + H-UI 弹窗/Datagrid/提交阻断类缺陷回归（W8 增补，详见 bemp-chrome-devtools-test/references/regression-patterns.md）

### 不适用场景
- 纯后端 API 测试 → 需 api-test-pro
- 性能测试 → 需 bemp-jmeter-test
- 安全测试 → 需专门安全工具
- 移动端测试 → 需移动端框架
- 非 BEMP 项目 → 流程映射不适用
- Vue3 组件实例遍历（$children 失效，需 findComponent/provide-inject）

## 四、工作流级模式

### P5 并行合并终验

- **规则**：≥2 个智能体并行修改同一模块后，必须由独立第三方（未参与该轮并行修改的智能体）以全量编译 + 全量测试执行合并终验；禁止采信各并行方自报的局部结果作为合并结论。
- **适用**：多智能体并行开发/修复存在文件交叉或共享依赖的场景（同一工程、同一配置层、同一前端入口映射）。
- **不适用**：严格按文件边界切分、互不触碰的并行任务（合并后执行一次轻量编译确认即可，无需全量测试）。
- **来源**：反洗钱四阶段校验需求中并行修改后未做统一终验，导致合并态问题被各方自报结果掩盖。

### P6 外部依赖标注协议

- **规则**：BLOCKED/⏸ 标注必须写明回归条件（何种数据/环境/配置/服务就绪后可执行），并随交付文档移交跟踪；禁止只写"BLOCKED"不写条件的空标注。
- **适用**：受外部数据、环境、服务、第三方配置制约的用例与交接事项（如等待特定测试数据、等待外部系统开通）。
- **不适用**：全自主可完成的任务（内部失败应走缺陷闭环与回退规则，而非外部依赖标注）。
- **来源**：反洗钱四阶段校验需求中部分用例因外部数据未就绪被标 BLOCKED，但回归条件缺失，交付后无法判断何时可恢复执行。

### P7 评审回退快速通道复审协议

- **规则**：评审回退修复后，复审按两步走——①修复方提交前必须逐项勾验修复清单，每项附落点证据（文件:行号 或检索结果），禁止整批口头声明"已修复"；②复审方走快速通道仅核对修复项（免全量重审），核对时以代码/文档事实为锚逐项验证，不采信自报。
- **适用**：评审问题修复面小于全量 30%、且修复不引入设计变更的场景（文案更正/SQL 修正/引用错位/统计口径等）。
- **不适用**：修复引发设计变更、新增用例占比过高、或首轮评审未完成的场景（须全量重审）。
- **来源**：六阶段签收校验用例评审回退修复后，快速通道复审抓出修复清单中 1 项遗漏（W9-05），验证了"逐项勾验 + 定向复审"闭环的必要性。

### P8 子智能体写入通道故障降级协议

- **规则**：子智能体遭遇 IDE 写入通道故障（Write/Edit/RunCommand/Glob/LS 超时或序列化异常）时：①先做通道级排查（替代写入通道 + 参数序列化变体），禁止立即放弃；②确认不可恢复后按降级处理——全部产出内容在最终回复中完整定稿（含逐文件落盘指引：目标文件/追加位置/追加方式/收尾复核检索式），标"⚠ 降级"，禁止虚构落盘成功；③通道恢复后由新子智能体按指引补落盘并检索复核，复核通过前该阶段不得视为完成。
- **适用**：子智能体执行期 IDE 桥接层故障；产出物可文本定稿的场景（用例文档/报告/配置条目）。
- **不适用**：产出依赖执行过程实时状态（如必须现场运行命令取回数据）且通道不可恢复时——应标 BLOCKED 写明回归条件（P6）后终止，禁止凭记忆补造数据。
- **来源**：六阶段签收校验测试用例编制阶段写入通道全故障，内容回复内定稿后由后续子智能体按指引补落盘成功（5 文件检索复核全通过）。

### P9 同文件多处编辑串行铁律

- **规则**：对同一文件的多处修改必须串行执行（一次一处、落盘确认后再下一处），并在收尾以全量检索验证所有修改点的最终落盘状态；跨文件编辑才可并行。并行 Edit 同一文件存在写入竞态，后写覆盖先写导致部分修改静默丢失。
- **适用**：任何技能/智能体对同一文件的多点修改（文档批量修正、配置多处增补、代码同文件多处编辑）。
- **不适用**：不同文件之间的并行修改（可安全并行）。
- **来源**：W8 期已发生一次；六阶段用例评审修复时再次发生（同文件 5 处首轮修改被覆盖丢失，改串行后逐项补修通过）——两次实证，非偶发，固化为铁律。

### P10 复用优先测试策略

- **规则**：测试资产承接一律以实盘为准，上游口述统计数字仅作线索，禁止凭口述数字直接重编全套或排期。
- **固定流程**：①盘点（Glob 用例目录 + 实盘基数核实）→ ②覆盖度映射表（功能点 ↔ 既有用例编号，逐项标注复用/修订/新增）→ ③增量修订（保持既有用例编号格式不重编，仅追加新编号）→ ④仅评审增量（复用项抽检、修订项与新增项全审）。
- **判断逻辑**：上游统计数字与实盘基数不一致 → 以实盘为准并向源头反馈偏差；无法实盘 → 显式声明"数字仅为线索"待核实。
- **适用**：需求迭代、回归测试、PRD 小版本升级等已有测试资产可复用的场景。
- **不适用**：全新模块（无既有资产可盘点）；资产结构差异大到映射表不可维护的场景。
- **来源**：W10-01；完整操作指南见 bemp-testcase-generator/references/reuse-first-strategy.md。

### P11 配置登记决策树

- **规则**：修改任何配置前先核实代码的实际读取通道，再按通道登记；禁止凭经验猜通道改配置（改错位置不生效，浪费排查轮次）。
- **固定流程**：核实读取通道（代码 `@Value` 注解 → env.properties / 参数中心取值 → 参数表 / 脚本读取 → _shared env-config 经 `${ENV:}` 占位解析）→ 按对应通道登记值 → `@Value` 通道登记后需重启服务才生效。
- **判断逻辑**：失败特征 = 报错信息出现 `${xxx}` 字面量 → 该值未注册到代码实际读取的通道（登记错位），按决策树重新定位通道。
- **适用**：任何配置增改场景（应用配置、参数中心、脚本环境值）。
- **不适用**：纯代码内常量（非配置通道，改配置无效，须改代码）。
- **来源**：W10-03。

### P12 测试数据三重校准

- **规则**：直插 SQL 落库前必须完成三重校准——①列宽/类型对齐目标表 describe 实测（逐列核对值长度与类型）；②关联字段值与业务主档表实查对照（文档模板值可能随主档演进过时，偏差时在数据文档 REMARK 注明修正依据）；③时效字段以业务日期（BusiDateService 基准）为基准回推，禁止按自然日期假设。
- **判断逻辑**：①缺位 → ORA-12899 类批量插入失败；②缺位 → 关联落空/命中失效（数据"在库但不生效"）；③缺位 → 生效起始晚于当前业务日导致时效过滤静态不命中假象。
- **适用**：凡生成 INSERT/UPDATE 直插数据的准备环节。
- **不适用**：仅查询核对、不落库的 SQL（无数据写入，无需校准）。
- **来源**：W10-04；已配置化：bemp-testcase-generator config/test-data-check.json（column-width-align-check / master-anchor-check / biz-date-validity-check，均 critical）。

### P13 ⏸补验闭环

- **规则**：⏸ 项必须登记回归条件（何种数据/配置/外部依赖就绪后可执行），条件触发后二轮定向补验，补验结果回写原用例（结论与证据），形成闭环。
- **判断逻辑**：补验结果与原预期不符 → 升级为缺陷走回退规则；登记时无法给出可触发条件 → 按 P6 重新审视是否真属外部依赖。
- **适用**：因外部数据/配置/依赖未就绪被暂缓（⏸）的用例与检查项。
- **不适用**：范围裁剪项（明确不做 → 标"范围外"，不做补验承诺）。
- **来源**：反洗钱全面测试中部分 ⏸ 项交付后无补验闭环，回归条件与结果回写缺失；与 P6 外部依赖标注协议衔接（P6 管"标注时写条件"，P13 管"条件触发后补验并回写"）。

### P14 并行任务数据时序隔离

- **规则**：多智能体并行操作同一 DB 时，数据断言必须标注时序快照（断言时刻非终态），或按"谁生产谁清理、错开生命周期"编排任务；终态结论以清理后复核为准。
- **判断逻辑**：断言对象可能处于他人事务窗口（他人未落库/未清理）→ 该断言为中间时序快照，不得直接判缺陷；列表行数/内容类断言尤其敏感。
- **适用**：并行回归、并行 E2E 等多智能体共享同一数据库的场景。
- **不适用**：单智能体串行执行；数据完全隔离（独立 schema 或独立业务键段，互不可见）。
- **来源**：W10-06。

### P15 MCP 通道污染降级

- **规则**：识别特征成立（同 server 全部调用持续超时/序列化错误 + 终止进程组/重启 MCP 无效）→ 立即切降级通道（如 CDP → Playwright）续跑，在降级通道复验污染前未完成的断言，降级记录写入报告留档；避免反复重试浪费轮次。首次瞬时超时应先重试一次再判污染。
- **判断逻辑**：单次超时 → 重试一次；同 server 全部调用持续超时且重启无效 → 判一次性污染，立即降级，禁止继续重试。
- **适用**：任何 MCP server 通道故障场景（浏览器类/数据库类/工具类 MCP 均适用）。
- **不适用**：单工具偶发超时（重试即恢复，不构成污染特征）。
- **来源**：W10-05；通道切换策略详见 _shared/tool-switching-strategy.md。

### P16 已下线功能回归检测与再次废弃七步法

- **规则**：发现"已下线功能重新出现"（需求文档已删、功能仍出现）时，按 S1-S7 七步法闭环：检索定位（功能关键词全库检索，圈定前端页面/国际化/后端接口/需求文档四层改动面）→ 文档/代码双轨核对三分类 → 回归归因（@modify 注释/git log 定位引入点，识别关联缺陷单，还原理由与需求文档冲突时以文档为准）→ 删除面清单化（按钮→方法→死导入→国际化死键→接口→专属注入逐项标删/留，共用依赖保留并注明理由）→ 智能体通道精确编辑 → 主对话落盘核验（Grep 残留+死引用+结构完整性，不采信子智能体自述）→ 审计轨迹追加（改记录只追加不改历史行）与关联缺陷单补记方向修正说明（防第三次还原）。
- **判断逻辑**：三分类决策树——文档未删 → 先回退需求梳理补档再下线；代码从未改造 → 直接执行下线；代码回归 → 先归因（关联缺陷单还原理由失效）再删。权威源优先级：**需求文档当前版本 > 历史代码 > 缺陷单历史结论**。防回归铁律：缺陷修复"还原历史代码"前必须核对需求文档当前版本状态，禁止仅凭历史代码判断功能应当存在。
- **适用**：功能下线/废弃类需求；"功能还在"类反馈归因排查；缺陷修复误还原检测；重构前死代码盘点。
- **不适用**：新功能开发（走正常开发流）；功能逻辑变更（修改非删除）；多功能交织的大重构。
- **来源**：某已下线功能被缺陷修复误还原（文档已删、代码回归），完整七步法、D1-D4 判断逻辑与虚构示例见 bemp-personalized-dev/assets/guides/offboarding-guide.md；评审规则见 bemp-backend-code-review config/review-flow-checklist.json RF-008；工具失败点见 W11-01~W11-03。

### P17 运行进程新鲜度三重验证

- **规则**：测试执行前必须确认"运行进程加载的就是目标代码"——三重链：进程启动时间 ≥ 部署产物 mtime ≥ 最新源码修改时间（或 git 最新提交时间）；任一倒挂即判"旧代码运行时"，先重启再测试，禁止带病执行。
- **判断逻辑**：铁证判别=已删除接口的可达性差异（旧代码 HTTP 200 / 新代码 404/路径不存在）；辅助特征=新增校验文案不出现、新参数不生效。注意 W9-01（jar 旧包）与本模式（进程旧包）是两道独立检查，都要做。
- **适用**：任何"改代码→重启→测试"链路；修复后回归验证的前置确认。
- **不适用**：测试目标本身是旧版本代码的专项回归（此时显式声明"锁版本"并在报告注明）；纯文档/前端无后端代码变更的任务。
- **来源**：W12-01；已配置化：bemp-webapp-testing config/data-readiness-check.json（runtime-code-version-check）；启动侧配套见 bemp-automation-startserver scripts/check-artifact-freshness.ps1。

### P18 环境配置数据就绪预检

- **规则**：功能测试执行前，除业务数据外必须预检"环境配置数据"三类：菜单权限注册（授权表回读）、定时任务登记（TT_TASK 类表回读）、业务参数配置（参数表回读）；预检 SQL 声明在配置中（表名/字段名/期望值占位符化），未就绪项执行前批量补齐或显式 BLOCKED。
- **判断逻辑**：预检缺失 → 执行中集中暴露 → 批量 BLOCKED + 紧急补数据打乱执行节奏（本轮 17 条 BLOCKED 均源于此）；预检发现缺失 → 判断属交付 SQL 未执行（补执行+入增量脚本）还是外部依赖（标 BLOCKED+回归条件）。
- **适用**：依赖 DB 配置数据（菜单/参数/任务/字典）的功能测试；新环境首次执行前。
- **不适用**：纯代码审查类用例；环境已验证稳定且无配置变更的常规回归（可按配置开关降频）。
- **来源**：W12-02；已配置化：bemp-webapp-testing config/data-readiness-check.json（env-config-data-precheck）。

### P19 中断重派终止确认与幂等可重入

- **规则**：重派被中断的后台任务前必须确认原任务真实终止（killed 通知≠进程立即终止，可能迟到完成交付）；写库/改环境类任务设计为幂等可重入（DELETE 按业务键+INSERT、回读唯一性断言兜底），使双写残留可被收敛。
- **判断逻辑**：kill 通知后收到该任务完成通知 → 原任务实际已完成，比对两份产出取最新或合并，禁止盲目重跑；无法确认时 → 新任务先做全量回读防重复检查再执行增量。
- **适用**：多智能体后台任务编排；环境变更类任务（DB/服务/配置文件）。
- **不适用**：纯读取类任务（无写副作用，重跑无害）；已确认进程终止且产出已回收的场景。
- **来源**：W12-04；与 P14（并行时序隔离）互补——P14 管断言语义，P19 管任务生命周期。

### P20 变更影响清扫（用例套件矛盾断言检测）

- **规则**：用例修订/作废/功能下线类变更落盘后，必须以本次变更的关键词（功能名/按钮名/接口名）Grep 全量用例文档（含存量套件与索引），识别三类残留：存在性断言反转（旧"按钮可用"vs 新"按钮不存在"）、过时测试假设（实现已推翻）、统计联动漏改（文档统计表/索引/合计行）。
- **判断逻辑**：同套件内对同一对象存在方向相反的断言 → 必然一方失效，按需求文档当前版本裁决；范围外文档发现残留 → 如实申报不越界修改，列入交付物"已知问题"或单独同步任务。
- **适用**：功能下线/口径变更/规则翻转类需求迭代后的用例维护；复用优先策略的增量修订环节。
- **不适用**：纯新增功能（无旧断言可清扫）；一次性独立用例文档（无跨文档引用）。
- **来源**：W12-05；操作清单见 bemp-testcase-generator references/change-sweep-checklist.md。

### P21 索引 summary 闭合校验

- **规则**：test-index 类聚合索引每次变更后强制闭合校验：summary.total_cases = 条目数、total_estimated_count = Σ case_count、by_subsystem/by_priority 分组合计 = total_cases；不闭合即修复后落盘，禁止只改条目不重算汇总。
- **判断逻辑**：条目与汇总不一致 → 消费方（覆盖率统计/执行范围圈定）失真；校验成本低（一次聚合比对），固定在索引维护收尾步骤。
- **适用**：任何"条目明细 + 汇总区块"双层结构的索引文件（JSON/YAML/MD 统计表同理）。
- **不适用**：无汇总区块的纯清单文件。
- **来源**：W12-06。

### P22 扫描器认可的 sanitizer 形态库

- **规则**：修复商用污点分析扫描器（路径遍历/文件上传类）报出的安全缺陷时，防御代码必须采用扫描器普遍认可的 sanitizer 形态，否则修复本身仍被报出：认可=白名单正则校验（预编译 Pattern 全匹配）、文件头魔数校验、框架安全注解；不认可=手写 contains/indexOf 黑名单、仅扩展名校验、仅大小校验。
- **判断逻辑**：修复后扫描仍报同一位置 → 优先怀疑 sanitizer 形态不被识别，按形态库升级校验写法（黑名单→白名单正则），而非反复调整文案；纵深防御逻辑（normalize+前缀守卫等）保留不动，升级只改"过滤形态"。
- **适用**：污点分析类扫描器（路径遍历/文件上传/注入类）的缺陷修复与预防御。
- **不适用**：SonarQube 规则类问题（规则 ID 映射体系不同，走 bemp-sonarqube-mcp 修复链）。
- **来源**：W12 期扫描收敛实战（contains 黑名单 9 条高危复报 → 白名单正则收敛）；形态库详见 bemp-personalized-dev references/sanitizer-patterns.md。
