### 2.2 环境配置

所有技能模块共享全局环境配置，位于 `_shared/env-config.json`：

```json
{
  "paths": {
    "workspaceRoot": "${ENV:BEMP_WORKSPACE_ROOT}",
    "banksProjectPath": "${ENV:BEMP_WORKSPACE_ROOT}\\banks\\ext-hnnxbank",
    "frontendProjectPath": "${ENV:BEMP_WORKSPACE_ROOT}\\frontend"
  },
  "services": {
    "redis": { "port": 6379 },
    "zookeeper": { "port": 2181 },
    "springboot": { "port": 8010, "debugPort": 5005 },
    "frontend": { "port": 8091 },
    "sonarqube": { "port": 9000 }
  },
  "database": {
    "oracle": { "host": "${ENV:ORACLE_HOST}", "port": 1521 },
    "mysql": { "host": "${ENV:MYSQL_HOST}", "port": 3306 }
  }
}
```

**配置占位符机制**：路径中使用 `${ENV:VAR_NAME}` 占位符，运行时通过 `_shared/Resolve-EnvConfig.ps1` 解析。解析优先级：环境变量 → `environmentDefaults` 默认值 → 空字符串警告。

**首次配置步骤**：

1. 设置核心环境变量（或在 `env-config.json` 的 `environmentDefaults` 中配置默认值）：
   ```powershell
   $env:BEMP_WORKSPACE_ROOT = "d:\code\QJ\BEMP5.0DEV"
   $env:JAVA_HOME = "D:\code\Java\jdk1.8.0_341"
   $env:MAVEN_PATH = "D:\code\apache-maven-3.6.3\bin\mvn.cmd"
   $env:NODE_PATH = "D:\code\nodejs14\node.exe"
   $env:REDIS_EXE = "D:\code\Redis-x64-5.0.14.1\redis-server.exe"
   $env:ZOOKEEPER_EXE = "D:\code\apache-zookeeper-3.8.3-bin\bin\zkServer.cmd"
   ```

2. 数据库连接配置（修改 MCP 配置文件，路径见各技能 `db-config.json` → `mcpConfigRef`）

3. 验证环境：启动服务后访问 `http://127.0.0.1:8091/` 确认前端可用

### 2.3 技能调用方式

BEMP 技能通过 Trae IDE 的智能体体系调用，**禁止直接调用 Skill 工具**（`bemp-advanced-doc-generator` 除外，需通过 `document-delivery-engineer` 智能体）。

| 调用方式 | 适用场景 | 示例 |
|---------|---------|------|
| 自然语言触发 | 日常使用 | "帮我启动服务"、"生成测试用例" |
| Task 工具指定智能体 | 流程化操作 | `subagent_type="bemp-personalized-developer"` |
| 命令行脚本 | 自动化/CI | `.\start-bemp-env.ps1 -Service redis` |

#### 4. bemp-generate-prd — PRD 需求文档生成

| 属性 | 值 |
|------|-----|
| **目录** | `bemp-generate-prd/` |
| **触发词** | `生成PRD`、`生成需求文档`、`完善需求`、`会议纪要转需求` |
| **对应智能体** | `bill-requirement-analyst` |
| **版本** | v1.1.0 |

**核心能力**：BEMP 票据系统 PRD 智能生成。将会议纪要、需求草稿、原型图转为结构化 PRD。三角色审查自动补全业务规则、合规细节与交互体验。

**五阶段工作流**：
1. **文档转换** — docx/txt/md/粘贴文本 → Markdown
2. **图片识别** — Vision 能力识别 UI 截图/原型图（需带视觉能力的大模型）
3. **需求提取** — 保持原文一字不改，AI 补充用 `【补充】` 标记
4. **三角色审查** — 票据业务专家 + 票交所合规审查员 + 体验审查员
5. **生成输出** — `[OriginalStem]-v1.md`（主文档）+ `[OriginalStem]-待确认-v1.md`（待确认清单）

**迭代机制**：v1 初版含待确认清单 → 用户确认后生成 v2 → 逐步收敛。已确认的补充内容移入正文，不需要的删除，待讨论的保留标记。

**关键文件**：
- `references/bill-business-rules.md` — 票据业务专家规则库
- `references/compliance-rules.md` — 票交所合规审查规则库
- `references/ux-rules.md` — 票据系统体验审查规则
- `references/image-analysis-template.md` — 图片识别强制模板
- `references/document-templates.md` — 输出文档模板

#### 7. bemp-sonarqube-mcp — SonarQube 代码质量扫描

| 属性 | 值 |
|------|-----|
| **目录** | `bemp-sonarqube-mcp/` |
| **触发词** | `sonar扫描`、`质量门禁`、`代码质量`、`quality gate` |
| **对应智能体** | `bemp-implementation-engineer` |

**核心能力**：基于 SonarQube MCP 的质量门禁检查、新增代码问题扫描、代码片段分析、问题分类与修复建议。

**完整工作流**：
1. 服务器检测与启动（自动检测端口9000，未运行则自动启动）
2. 连接验证与项目确认
3. 功能模块代码定位
4. 质量门禁检查（覆盖率≥80%、重复率≤3%、新增问题=0）
5. 问题扫描（BLOCKER > HIGH > MEDIUM > LOW 优先级）
6. 问题分类与报告输出
7. 修复建议
8. 修复验证

**关键设计原则**：
- 服务器先行：所有扫描操作前必须确保 SonarQube 服务已启动
- BEMP 上下文感知：`@CloudComponent`、`@CloudReference` 等框架注解可能触发误报，需结合上下文判断
- 增量扫描：只扫描新增/修改的文件

**关键文件**：
- `config/scan_config.json` — 项目配置、服务器配置、模块路径映射
- `scripts/start-sonarqube.ps1` — SonarQube 服务器检测与启动
- `references/bemp-rule-overrides.md` — BEMP 项目规则豁免与误报处理

└────────────────────────────────────────┘
         ↓ (SpringBoot 依赖 Redis + ZK 就绪)
┌─ 应用层（并行启动，无需等待彼此） ────┐

└────────────────────────────────────────┘

**命令模板**：

# 脚本路径

.\start-bemp-env.ps1 -Service frontend -QuickStart

# 查看状态

.\start-bemp-env.ps1 -Service <服务名> -ForceRestart

**参数说明**：

| 参数 | 适用服务 | 作用 |
|------|---------|------|

| `-ForceRestart` | 全部 | 强制停止占用端口的进程后重启 |
| `-AutoRestart` | 全部 | 智能模式：运行中自动停止后重启，未运行正常启动 |

**核心规则**：
- 每个服务必须在独立 IDE 终端中启动
- 前端与后端无启动依赖，应同时启动以节省等待时间

- 重启即强制：用户要求"重启"时自动停止旧进程后重新启动

#### 15. bemp-db-operator — 数据库标准化操作

| 属性 | 值 |
|------|-----|
| **目录** | `bemp-db-operator/` |
| **触发词** | `数据库操作`、`执行SQL`、`数据查询`、`数据回退` |
| **对应智能体** | `bemp-implementation-engineer` |
| **版本** | v2.4.0 |

**核心能力**：通过 MCP 实现 Oracle/MySQL 双引擎数据库标准化操作，提供 SQL 执行 → 结果复核 → 异常回退的完整闭环。

**双引擎支持**：

| 操作 | Oracle MCP | MySQL MCP |
|------|-----------|-----------|
| 查询 | `mcp_oracle-mcp_execute_query` | `mcp_MySQL_execute_sql` |
| DML/DDL | 不支持（需SQL*Plus） | `mcp_MySQL_execute_sql`（支持安全执行模式） |
| 表结构 | `mcp_oracle-mcp_describe_table` | `mcp_MySQL_execute_sql("DESCRIBE {table}")` |

**执行流程**：
1. 读取配置 → 2. 建立连接 → 3. 编码初始化 → 4. 版本检测 → 5. SQL预检查 → 6. 执行前快照 → 7. 执行SQL → 8. 结果复核 → 9. 生成报告 → 10. 异常回退（如需）

**MySQL 安全执行模式**：事务包裹执行，验证后提交，失败自动回滚。DDL语句隐式提交无法被ROLLBACK，安全模式仅对DML有效。

**智能体委托策略**：主智能体可能缺少 Oracle MCP 工具，需委托 `bemp-implementation-engineer` 子智能体执行。多级降级：MCP → 子智能体委托 → 命令行工具 → 报错终止。

**命令行执行**：
```powershell
# Oracle DML/DDL（MCP不支持，必须用sqlplus）
.\scripts\execute-oracle-sql.ps1 -SqlFile "D:\scripts\menu.dml.sql" -ConfigFile "config\db-config.json"

# MySQL CLI 备选
.\scripts\execute-mysql-sql.ps1 -SqlFile "D:\scripts\menu.dml.sql" -ConfigFile "config\db-config.json"

# 数据导出
.\scripts\export-db-data.ps1 -TableName "TB_BILL_INFO" -ConfigFile "config\db-config.json" -TimeField "CREATE_TIME" -Days 7 -Format "md"
```

**关键配置文件**：
- `config/db-config.json` — 数据库连接参数、类型配置、智能体工具映射
- `config/execution-policy.json` — 执行策略（超时/安全模式/批量/编码/版本检测/连接保活）
- `config/query-templates.json` — 常用查询模板
- `config/version-compat.json` — 数据库版本兼容性矩阵

### 4.2 环境变量占位符机制

所有配置文件统一使用 `${ENV:VAR_NAME}` 占位符，通过 `_shared/Resolve-EnvConfig.ps1` 解析：

```powershell
# 在脚本中引用
. "$PSScriptRoot\..\..\_shared\Resolve-EnvConfig.ps1"
$resolvedValue = Resolve-EnvPlaceholder "${ENV:JAVA_HOME}"
$globalConfig = Get-GlobalEnvConfig
```

**解析优先级**：系统环境变量 → `env-config.json` 的 `environmentDefaults` → 空字符串 + 警告

### 4.3 银行配置切换

多个技能支持银行切换，配置位置各不相同：

| 技能 | 配置文件 | 切换方式 | 可用银行数 |
|------|---------|---------|-----------|
| 后端代码审查 | `bemp-backend-code-review/config/bank-config.json` | 修改 `currentBank` | 按需添加 |
| 前端代码审查 | `bemp-frontend-code-review/scripts/review-config.json` | 修改 `bankName` 或 `--bank=xxx` | 12家 |
| 测试用例生成 | `bemp-testcase-generator/config/generator-config.json` | 修改 `active_bank` | 按需添加 |
| Web自动化测试 | `bemp-webapp-testing/config/test_config.json` | 修改 `active_bank` 或 `--bank` | 按需添加 |
| 适配器开发 | `bemp-adapter-dev/config/bank-config.json` | 修改银行配置 | 按需添加 |

> ⚠️ **银行环境同步**：`generator-config.json` 与 `test_config.json` 各自维护 `active_bank`，切换银行时两个配置需同步更新。

## 六、问题排查与解决方案

### 6.1 环境启动问题

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| Redis 启动失败 | 端口6379被占用 | `.\start-bemp-env.ps1 -Service redis -ForceRestart` |
| SpringBoot 启动报连接错误 | Redis/ZK未就绪 | 先启动Redis和ZK，等待就绪后再启动SpringBoot |
| 前端启动白屏 | 后端未启动或API不可达 | 确认后端8010端口正常，检查代理配置 |
| 端口被占用 | 旧进程未释放 | `netstat -ano | findstr :8010` → `taskkill /PID <pid> /F` |
| JVM内存不足 | 默认堆内存偏小 | 修改 `config/config.json` 中 `jvmOptions` 的 `-Xmx` 值 |

### 6.2 代码审查问题

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| 国际化文本不显示 | zh-CN.js未定义或键名拼写错误 | 添加键值对，检查命名规范 `{bankName}.{模块}.i.{功能}.{字段}` |
| API调用报错 | extParam格式/路径不匹配 | 用requestDto格式替代extParam，核对路径和HTTP方法 |
| `@CustomizedBean` 误用 | extends产品实现类未加/Controller误加 | extends产品Impl→加；仅implements接口→不加；Controller→不加 |
| DTO参数获取为null | 参数名大小写不一致 | 确保前后端参数名完全一致，DTO有getter/setter |
| Content type not supported | @RequestBody vs form-data冲突 | 去掉@RequestBody(推荐)或前端改JSON |

### 6.3 数据库操作问题

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| 中文乱码 | 终端GBK与数据库UTF-8不匹配 | 执行编码初始化：MySQL `SET NAMES utf8mb4`；终端 `chcp 65001` |
| Oracle DML/DDL无法执行 | Oracle MCP仅支持SELECT | 使用 `scripts/execute-oracle-sql.ps1` 通过SQL*Plus执行 |
| MCP工具不可用 | 主智能体缺少Oracle MCP | 委托 `bemp-implementation-engineer` 子智能体执行 |
| MySQL安全模式回滚失败 | DDL语句隐式提交 | DDL无法回滚，仅DML受事务保护 |
| 连接超时断开 | 超过wait_timeout | 连接保活机制自动处理（间隔300秒） |

### 6.4 测试相关问题

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| Playwright连接超时 | 使用localhost而非127.0.0.1 | 所有URL统一使用 `127.0.0.1` |
| HUI组件fill_form无效 | HUI组件需特殊输入方式 | 使用 `evaluate_script` + `dispatchEvent('input')` |
| Vue路由未注册 | 懒加载路由需菜单点击触发 | 先点击菜单注册路由，再通过URL导航 |
| 弹窗残留阻塞 | 弹窗未关闭就导航 | 关弹窗前不导航；残留则 `new_page` 重新登录 |
| ChunkLoadError | 前端构建不完整 | 重新执行前端构建，检查nginx配置 |
| 登录按钮文本含空格 | "登 录"而非"登录" | 使用包含空格的文本匹配 |

### 6.5 构建与部署问题

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| Maven编译失败 | Java版本/依赖问题 | `mvn compile -DskipTests`；检查pom.xml和JDK版本 |
| Git冲突 | 本地修改与远程冲突 | 按 `CONFLICT_ACTION` 配置处理（stop/warn/skip） |
| target目录锁定 | 其他进程占用 | `SKIP_CLEAN_ON_LOCK=true` 自动跳过clean |
| Jenkins构建后服务停止 | JENKINS_NODE_COOKIE未设置 | 启动命令前加 `set JENKINS_NODE_COOKIE=dontKillMe` |
| 终端乱码 | 编码不匹配 | 自动追加 `-Dfile.encoding=UTF-8` + `[Console]::OutputEncoding=UTF8` |

### 6.6 SonarQube 问题

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| SonarQube连接失败 | 服务未启动 | 运行 `scripts/start-sonarqube.ps1` 自动启动 |
| BEMP注解误报 | @CloudComponent等框架注解触发规则 | 参考 `references/bemp-rule-overrides.md` 标记误报 |
| 质量门禁未通过 | 覆盖率/重复率/新增问题超标 | 按报告逐项修复，优先处理BLOCKER/HIGH级别 |

### 6.7 JMeter 性能测试问题

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| HTML报告生成失败 | JTL非CSV格式 | 确认 `jmeter.properties` 含 `output_format=csv` |
| OOM错误 | JMeter堆内存不足 | 调整 `JMeter HEAP`：`-Xms512m -Xmx2048m` |
| 目标服务不可达 | 服务未启动 | 压测前先执行单次curl验证 |
| 生产环境误压 | 配置错误 | 安全校验黑名单匹配即拒绝 |
