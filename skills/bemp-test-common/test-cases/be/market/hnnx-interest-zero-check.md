# P0-P2 测试用例 - hnnxbank 票据应付利息为0弹窗拦截

> 来源：hnnxbank 个性化需求"单张票据应付利息为0时弹窗提示并禁止提交"
> 银行环境：hnnxbank（河南农信）
> 关联需求：转贴现买入/卖出/再贴现业务提交时校验首期应付利息（firstPayInterest）是否为零
> 代码实现：HnnxMarketValidateUtil.validateZeroInterestForRebuy / validateZeroInterestForSale
> 错误码：HNNX0BE320008
> 提示文案："票号XX的应付利息为0"

---

## 全局前置条件

### 1. 登录角色
- 所有用例均以 **hnnxbank 法人管理员** 身份登录系统

### 2. interestStatus 保障方式（适用于所有涉及利息校验的用例）
- 利息状态 `interestStatus = 1`（已计算）是零利息校验的前置条件
- 保障方式：通过前端利息计算功能触发，确认利息计算成功后再执行提交操作
- 如通过数据库直接修改 `firstPayInterest`，需确保 `interestStatus` 字段值同步更新为 1
- 执行测试前，通过数据库查询确认相关票据的 `interestStatus = 1`

### 3. 数据隔离说明
- 所有测试数据仅限 hnnxbank 机构及下级机构，确保数据隔离
- 使用非本机构数据执行测试时，结果可能不符合预期

## 测试数据准备

### 3.1 数据清单

| 数据类型 | 用途 | 涉及用例 | 构造方法 |
|----------|------|----------|----------|
| 正常票据（firstPayInterest > 0, interestStatus = 1） | 正常场景验证 | TC-MARKET-067~069 | 通过利息计算功能生成 |
| 零利息票据（firstPayInterest = 0, interestStatus = 1） | 零利息拦截验证 | TC-MARKET-070~074, 078~081, 083 | 见 3.2 |
| 负数利息票据（firstPayInterest < 0, interestStatus = 1） | 校验顺序验证 | TC-MARKET-075 | 见 3.2 |
| null 利息票据（firstPayInterest = null, interestStatus = 1） | 空值处理验证 | TC-MARKET-084 | 见 3.3 |
| 未计算利息票据（interestStatus != 1） | 状态校验验证 | TC-MARKET-085 | 见 3.3 |
| 含子票区间零利息票据 | 弹窗文案格式验证 | TC-MARKET-080 | 选择含子票区间的票据后修改利息 |

### 3.2 构造 firstPayInterest = 0 的数据方法

#### 方法一（推荐）：通过 SQL 直接 UPDATE（快捷可靠）

```sql
-- === 查询当前可交易的票据及其利息信息 ===
SELECT B.BILL_ID, B.BILL_NO, I.INTEREST_ID, I.FIRST_PAY_INTEREST, I.INTEREST_STATUS
FROM PJ_BILL_INFO B
JOIN PJ_BILL_INTEREST I ON B.BILL_ID = I.BILL_ID
WHERE B.ORG_ID = 'hnnxbank'  -- 替换为实际机构ID
  AND B.BILL_STATUS = 'normal'  -- 票据状态为正常可交易
  AND I.INTEREST_STATUS = 1     -- 利息已计算
ORDER BY B.BILL_ID;

-- === 将指定票据的 firstPayInterest 修改为 0 ===
-- 注意：务必先确认 interestStatus = 1，再执行 UPDATE
UPDATE PJ_BILL_INTEREST
SET FIRST_PAY_INTEREST = 0
WHERE BILL_ID = '目标票据ID'  -- 替换为实际票据ID
  AND INTEREST_STATUS = 1;

-- === 验证修改结果 ===
SELECT BILL_ID, FIRST_PAY_INTEREST, INTEREST_STATUS
FROM PJ_BILL_INTEREST
WHERE BILL_ID = '目标票据ID';
```

#### 方法二：通过利息计算功能构造（模拟真实业务流程）
1. 在买入/卖出申请页面，选择目标票据
2. 调整利率或计息天数，使系统计算出的首期应付利息 = 0
3. 确认利息计算成功（interestStatus = 1, firstPayInterest = 0）
4. 点击提交触发校验

> **注意**：方法二依赖于前端利息计算逻辑，如果业务规则不允许利息为 0 的计算结果，则使用方法一

#### 方法三：构造负数利息数据

```sql
-- 将指定票据的 firstPayInterest 修改为负数
UPDATE PJ_BILL_INTEREST
SET FIRST_PAY_INTEREST = -100.00
WHERE BILL_ID = '目标票据ID'
  AND INTEREST_STATUS = 1;
```

### 3.3 构造特殊状态数据

#### 构造 firstPayInterest = null 数据

```sql
-- 将指定票据的 firstPayInterest 置为 null
UPDATE PJ_BILL_INTEREST
SET FIRST_PAY_INTEREST = NULL
WHERE BILL_ID = '目标票据ID'
  AND INTEREST_STATUS = 1;
```

#### 构造 interestStatus != 1 数据

```sql
-- 将指定票据的 interestStatus 修改为 0（未计算）
UPDATE PJ_BILL_INTEREST
SET INTEREST_STATUS = 0, FIRST_PAY_INTEREST = 0
WHERE BILL_ID = '目标票据ID';
```

### 3.4 数据就绪检查与数据清理

#### 数据记录检查点
- 执行测试前，通过数据库查询确认各类型票据数量满足用例要求
- 检查 PJ_BILL_INTEREST 表中 firstPayInterest 和 interestStatus 字段值正确
- 记录修改前的 firstPayInterest 原始值，用于测试后恢复
- 预删除状态票据需确认 delete_flag 字段值正确

#### 数据清理

测试完成后，执行以下 SQL 恢复被修改的票据数据：

```sql
-- 恢复被修改的利息数据
UPDATE PJ_BILL_INTEREST
SET FIRST_PAY_INTEREST = 原值,  -- 替换为修改前的原始值
    INTEREST_STATUS = 1
WHERE BILL_ID IN ('票据ID1', '票据ID2', ...);
```
