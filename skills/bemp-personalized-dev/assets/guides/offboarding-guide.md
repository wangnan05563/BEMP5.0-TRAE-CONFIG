# 功能下线/废弃改造指南（含回归检测）

> 固化"功能下线/废弃"类改造与"已下线功能回归"排查的标准流程、判断逻辑与防回归铁律。
> 零硬编码：本文所有示例均为虚构占位示例，实际取值以本次需求与 [SKILL.md 配置加载](../../SKILL.md) 解析结果为准。

---

## 一、适用场景

**适用**：
- 功能下线/废弃类需求（页面手动触发入口 + 后端接口一并移除）
- "功能还在"类反馈的归因排查
- 缺陷修复误还原已下线代码的检测
- 重构前死代码盘点

**不适用**（转对应流程）：
- 新功能开发 → 个性化开发标准流程（见 SKILL.md 执行步骤）
- 功能逻辑变更（修改而非删除） → 正常修改流程
- 多功能交织的大重构 → 先拆分需求再逐个处理
- 文档未入档的功能下线 → 先回退需求梳理补档，再执行本流程

## 二、防回归铁律（最高优先级）

**缺陷修复"还原历史代码"前，必须核对需求文档/PRD 当前版本状态，禁止仅凭"历史代码中该功能存在"判断功能应当存在。**

- 适用于一切缺陷修复场景，不限于功能下线
- 历史代码 ≠ 当前需求基线；两者冲突时以需求文档当前版本为准（见 D4）

## 三、标准流程 S1-S7（速查表）

| 步骤 | 核心动作 | 产出 / 验证点 |
|------|---------|--------------|
| S1 检索定位 | 以 {function_keyword} 全库检索，圈定四层改动面：前端页面（{page_route}）、国际化文件、后端接口（{interface_path}）、需求文档 | 四层文件清单 |
| S2 双轨核对 | 需求文档基线状态 vs 代码当前状态 → 三分类（见 D1） | 分类结论 |
| S3 回归归因 | 读 @modify 注释 / git log 定位回归引入点；识别关联缺陷单（{defect_id}）；判断"当时还原的业务理由是否仍成立"——与需求文档当前版本冲突时以文档为准 | 归因结论 |
| S4 删除面清单化 | 按第五节删除链逐项标注"删/留"；被其他链路共用的依赖必须保留并注明理由 | 删/留清单 |
| S5 派发执行 | 走智能体通道派发，明确"精确编辑、不动共用功能"约束 | 修改完成 |
| S6 落盘核验 | 主对话执行：Grep 残留检查 + 死引用检查 + 结构完整性阅读；**不以子智能体自述为验收标准** | 核验 PASS |
| S7 审计与防回归 | 修改记录**追加**条目（不改历史行，保持审计轨迹）；关联缺陷单补记方向修正说明，防止被旧缺陷单第三次还原 | 审计闭环 |

## 四、判断逻辑 D1-D4

### D1 "功能还在"三分类决策树（S2 输出决定后续路径）

```
发现"功能还在"（文档已删、功能仍出现）
├─ 查修改记录（@modify / git log）
│  ├─ 存在还原引入点（关联缺陷单 {defect_id}）→ 代码回归
│  │   └─ 还原理由与需求文档当前版本冲突 → 理由失效 → S4-S7 再次废弃
│  └─ 无还原记录 → 代码从未改造 → S4-S7 执行下线
└─ 需求文档中功能未标记下线 → 文档未删 → 回退需求梳理补档后再走 S4-S7
```

### D2 共用依赖判断

待删的注入字段 / Service 方法 / 常量被**其他链路**（如定时任务、其他接口）引用 → **必须保留**，仅在 S4 清单注明"保留理由：被 {caller_chain} 引用"。仅本功能专属的依赖才列入删除面。

### D3 死代码链式清理

删除调用点后必须顺链检查：事件方法是否成为无调用死方法 → import 是否成为死导入 → 国际化键是否成为死键。逐级 Grep 引用计数，引用归零才删。

### D4 权威源优先级

**需求文档当前版本 > 历史代码 > 缺陷单历史结论。**
三者冲突时按此优先级裁决；缺陷单结论仅代表当时口径，不构成"功能应当存在"的证据。

## 五、删除链清单（S4 速查）

| 层 | 删除链（逐项标注"删/留"） |
|----|------------------------|
| 前端 | 页面按钮节点 → 事件方法 → 死导入 → 国际化死键 |
| 后端 | 接口方法 → 专属注入字段 → 专属 import |
| 文档 | 需求文档同步标注下线版本（审计追溯用） |

**红线**：被定时任务等共用链路引用的依赖一律保留并注明理由；删除动作收敛在个性化目录内，不动产品化代码。

## 六、虚构微型示例（占位符演示）

| 项 | 占位值 |
|----|--------|
| 下线功能 | {function_keyword}（页面手动触发按钮 + 后端 {interface_path}） |
| 涉及页面 | {page_route} |
| 关联缺陷单 | {defect_id} |

演示流：S1 检索得四层清单 → S2 判定"文档已删、代码回归" → S3 经修改记录确认 {defect_id} 修复时误还原、其业务理由与需求文档当前版本冲突 → S4 清单标注删（按钮/方法/死导入/i18n 死键/接口/专属注入）、留（共用 Service 方法：被 {caller_chain} 引用） → S5 智能体精确编辑 → S6 Grep {function_keyword} 零残留且无死引用 → S7 @modify 追加下线条目、{defect_id} 补记方向修正说明。
