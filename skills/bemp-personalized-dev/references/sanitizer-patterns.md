# 扫描器认可的 Sanitizer 形态库

> 对应复盘模式：_shared/test-workflow-retrospective.md **P22**（失败点 W12 期扫描收敛实战）
> 适用对象：商用污点分析扫描器（路径遍历/文件上传/注入类）报出的安全缺陷修复；**不适用** SonarQube 规则类问题（走 bemp-sonarqube-mcp 修复链）

## 一、核心结论

污点分析扫描器按"source → 是否经过被认可的 sanitizer → sink"判定告警。**防御代码若采用不被认可的形态，修复本身仍被报出**（本行实战：手写 contains 黑名单修复路径遍历后，9 条高危全部复报；改为白名单正则后形态可识别）。

## 二、形态认可映射表

| 校验形态 | 扫描器识别度 | 说明 |
|---------|------------|------|
| 白名单正则校验（`static final Pattern` 预编译 + `matches()` 全匹配） | ✅ 认可 | 首选形态；正则必须"全匹配"而非 `find()` 局部命中；模式常量提取到类级别 |
| 文件头魔数校验（读取前 N 字节与魔数常量比对） | ✅ 认可 | 文件上传场景与 Content-Type 白名单配合使用，服务端自证防伪造 |
| Content-Type 白名单校验 | ✅ 认可（弱） | 可被伪造，仅作粗筛；必须与魔数校验叠加才闭环 |
| 框架安全注解/标准安全 API | ✅ 认可 | 优先用框架既有安全组件 |
| 手写 contains/indexOf 黑名单（`contains("..")`/`contains("\\")` 等） | ❌ 不认可 | 防御语义成立但形态不被识别，污点流不被截断 |
| 仅扩展名校验（endsWithIgnoreCase） | ❌ 不认可 | 可伪造后缀；需魔数校验兜底 |
| 仅文件大小校验 | ❌ 不认可 | 只防 DoS 不防内容注入 |
| normalize + startsWith 前缀守卫 | ⚠️ 不定 | 作为纵深防御保留（逻辑正确），但不指望它让扫描器消项——消项靠上游白名单截断污点 |

## 三、修复决策树

```
扫描器报安全缺陷（路径遍历/文件上传/注入）
    ↓
确认污点源类型：用户输入 / 配置注入（@Value 等）/ 服务端生成
    ↓
已有防御但复报？→ 是：按形态映射表升级校验写法（黑名单→白名单正则），纵深防御逻辑保留不动
                → 否：补齐"认可形态"校验链（白名单正则/魔数/注解）
    ↓
配置注入型污点（扫描器视 @Value 为环境变量源）：在消费入口统一白名单校验三个维度
  ①文件名/标识符：字符集白名单+负向排除 .. 段（如 ^(?!\.\.)[A-Za-z0-9._-]+$）
  ②日期/编号类：定长格式白名单（如 ^\d{8}$）
  ③路径根目录：字符集白名单（允许盘符/分隔符，禁 <>|"*? 与 .. 段）
    ↓
兼容性自查：白名单字符集必须覆盖存量合法值（配置前缀/文件名实际值逐一核对，值来自配置解析链）
    ↓
编译验证 + 复扫确认消项（复扫前在交付物标"⚠ 消项待确认"）
```

## 四、判断边界

- **适用**：路径遍历（CWE-22 类）、文件上传（CWE-434 类）、注入类（污点型）缺陷修复；安全加固的预防御设计。
- **不适用**：SonarQube 规则问题（规则 ID 映射，走 bemp-sonarqube-mcp）；业务逻辑型安全需求（权限/越权，走 PRD 校验规则链而非 sanitizer）。
- **遗留确认项**：不同扫描器引擎对正则形态的具体识别有差异，修复后以**复扫结果**为最终消项依据；复扫仍报时优先排查"正则为 find 而非 matches""Pattern 未预编译到常量""白名单字符集过宽含分隔符"三类形态偏差。

## 五、本行实战锚点（2026-09-06 扫描收敛）

- SyncJobUtils.resolveDataFile：contains 黑名单（9 条高危复报）→ FILE_NAME_PATTERN/DATE_STR_PATTERN/ROOT_PATH_PATTERN 三段白名单，normalize+startsWith 前缀守卫保留
- 两 Branch 控制器 validateImportFile：扩展名+大小 → 追加 Content-Type 白名单（vnd.ms-excel/openxml.sheet/octet-stream）+ 魔数双校验（xls=OLE2 头 D0CF11E0A1B11AE1、xlsx=ZIP 头 PK0304）
