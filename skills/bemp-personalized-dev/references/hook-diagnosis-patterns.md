# 钩子诊断模式：切面/拦截器/开关类"业务成功但效果未生效"缺陷排查

> **触发场景**：①钩子/切面/拦截器/开关/配置驱动类功能"业务办理成功但应产生的效果未生效"缺陷的排查定性 ②需产出远程环境（内网/生产）核实用 SQL 判别集 ③钩子跳过分支补留痕日志或等同判断粒度改造。案例溯源：内网反馈"转贴现买入额度未占用"（2026-09，个性化切面自承自贴行号级判定误判，复盘沉淀 D1-D7）。
>
> 文中 `{placeholder}` 均为占位符（`{参数表名}`、`{开关参数键}`、`{配置表名}`、`{业务唯一键}`、`{钩子依赖字段}`、`{归属表名}`、`{流水表名}` 等），实际值按目标环境 schema 解析，禁止硬编码；"实例"栏引用的真实类名/表名/字段仅为本行案例记录，**不构成通用规则，复用时必须替换为目标环境真实值**。
>
> **适用边界**：✅ 切面/拦截器/钩子/开关/配置驱动的"业务成功但效果未生效"缺陷、产品化+个性化双层同源架构、远程环境协作排查；❌ 前端渲染类缺陷（走 page-assembly-patterns）、有报错堆栈的缺陷（直接看异常，无需定性分流）、性能问题。

## 快速决策树（先走此树，只读命中分支）

```
现象：业务办理成功，但钩子应产生的效果未出现？
├─ 否（业务直接报错/有堆栈） → 不适用本文档，直接按异常定位
└─ 是 → 定性"静默跳过类缺陷"，走 D1 定性分流
    ├─ 个性化钩子与产品化同源（同一查询/同一信号源） → 先走 D3 同源分叉判别收敛
    └─ 同源关系不明 → 直接读钩子代码走 D2 关卡清单法
    ↓
远程环境无法本地复现 → D4 SQL 判别集交远程方逐条执行回传（D5 截图取证规则贯穿）
    ↓
定性完成 → D6 修复模式三件套（D7 环境隔离约束全程：远程结论以远程取证为准）
```

## 一、D1 定性分流：先分"静默跳过"还是"报错路径"

**通用化表述**：接到"效果未生效"类反馈，第一个动作是定性缺陷路径，它决定全部排查方向——

- 业务成功 + 效果未生效 = **静默跳过类**：排除报错路径，排查方向指向钩子/切面/开关分支的 continue/return 跳过点；
- 业务失败 = **报错路径**：直接看异常堆栈定位，无需本模式。

定性错误的代价：按报错路径翻遍日志找不到任何异常记录（静默跳过本来就不打日志），浪费整轮排查；反之对真正的报错类缺陷套用本模式属于过度流程。

**本次实例**（真实案例，下同）：内网反馈"转贴现买入额度未占用"——转贴现买入交易办理成功（交易流水正常），额度占用效果未出现。定性为静默跳过类：排查方向指向额度占用链路上的个性化切面跳过分支，而非异常处理。

## 二、D2 关卡清单法：枚举"入口到生效"全部判定关卡

**通用化表述**：读钩子/切面代码，枚举从方法入口到生效动作之间的**全部判定关卡**，每关标注"不过时的表现"：

| 关卡类型 | 不过时的典型表现 |
|:---|:---|
| 开关未开 / 配置未命中 | 静默跳过或 warn 日志（按实现而定） |
| 业务条件判定不通过 | continue/return，常无日志（**高危静默点**） |
| 依赖要素缺失（`{钩子依赖字段}` 为空） | 跳过；若被空 catch 吞掉则完全静默 |
| 生效动作执行失败 | 通常有报错（不属于静默类，回 D1 复核定性） |

**反推规则**：用"现象是否报错"反推卡在哪层——现象无任何报错 → 卡在静默关；现象有 warn 日志 → 卡在有日志关；现象抛业务异常 → 不属于静默类。清单必须覆盖到生效动作为止，漏一关就可能漏掉真卡点。

**本次实例**：读 HnnxAcceptBankCreditAspect.isSelfAcceptSelfDisc 枚举关卡：①切面是否切入（无日志）→ ②自承自贴判定是否命中（continue 静默跳过，无日志）→ ③占用动作是否执行（有流水）。现象"无报错且无占用流水" → 收敛到第②关：行号级相等判定在转贴现场景误命中。

## 三、D3 同源分叉判别：产品化成功 ⇒ 共同前置必然通过

**通用化表述**：个性化钩子与产品化逻辑**同源**（同一查询/同一信号源，如共用同一配置表查询、同一入参要素）时——

```
产品化路径执行成功（有流水/数据痕迹）
    ⇒ 共同前置（配置 / 开关 / 入参要素）必然通过
    ⇒ 问题收敛到个性化特有分支
```

这一步能将排查范围砍半以上，远程环境协作时**优先执行**——共同前置的多轮往返核实可以整体免掉。

**本次实例**：个性化额度占用切面与产品化占用逻辑消费同一票的业务要素（同一信号源），产品化侧正常出占用流水 ⇒ 票据要素/前置配置无缺失 ⇒ 问题收敛到个性化特有的"自承自贴判定"分支，共同前置核实全部免查。

## 四、D4 SQL 判别集模板（远程协作排查核心交付物）

**通用化表述**：远程环境无法本地复现时，产出 SQL 判别集交远程方逐条执行回传。**每条 SQL 必须附三段式判读说明**（结果 A → 结论/下一步；结果 B → 结论/下一步），禁止只发 SQL 不附判读——远程方拿到裸 SQL 无法自行定性，必然多一轮往返。判别顺序：开关 → 配置（含归属确认）→ 产品化痕迹 → 钩子依赖要素。

### SQL-1 开关参数表查值

```sql
SELECT {参数值字段}, {状态字段}
  FROM {参数表名}
 WHERE {参数键字段} = '{开关参数键}';
```

判读：
- 有记录且参数值=预期开启值 → 开关通过，继续 SQL-2；
- 无记录或参数值=关闭值 → 开关未开即根因，转配置修复，排查终止。

### SQL-2 配置表查值（含归属确认，防配置脏数据误导）

```sql
-- 第一步：按业务键查配置
SELECT {配置字段}, {归属字段}
  FROM {配置表名}
 WHERE {业务唯一键} = '{目标业务键}';

-- 第二步（归属确认）：对查出的行按归属字段反查其业务归属
SELECT {归属名称字段}, {归属状态字段}
  FROM {归属表名}
 WHERE {归属键字段} = '{第一步查出的归属值}';
```

判读：
- 第一步无记录 → 配置缺失即根因，转配置补录；
- 第一步有记录、第二步归属与目标业务**相符** → 配置通过，继续 SQL-3；
- 第一步有记录、第二步归属与目标业务**不符** → 配置脏数据误导（按业务键查出的行实际归属其他业务线），**不得采信第一步结果**，回配置维护口径核实。

### SQL-3 产品化流水表查痕迹

```sql
SELECT {流水关键字段}
  FROM {流水表名}
 WHERE {业务唯一键} = '{目标业务键}'
   AND {流水类型字段} = '{目标流水类型}';
```

判读：
- 有流水 → 产品化链路+共同前置通过（结合 D3 收敛到个性化分支），继续 SQL-4；
- 无流水 → 共同前置存疑，回 SQL-1/SQL-2 复核。

### SQL-4 业务数据表查钩子依赖字段非空性

```sql
SELECT {钩子依赖字段}
  FROM {业务表名}
 WHERE {业务唯一键} = '{目标业务键}';
```

判读：
- 依赖字段为空/NULL → 钩子因要素缺失跳过即根因，转上游取数链路排查；
- 依赖字段非空 → 要素齐备，问题在钩子判定逻辑本身（回 D2 关卡清单定位具体关卡）。

**本次实例**：实际判别集按上述骨架落位——SQL-1 查业务参数开关 → SQL-2 查额度配置并做归属确认（按产品码查出的行经归属复核确认真实业务线）→ SQL-3 查产品化占用流水 → SQL-4 查票据主档承兑行/贴现行行号非空性。最终 SQL-4 回传"要素齐备" + SQL-3 回传"产品化有流水" ⇒ 收敛到切面判定逻辑，与 D3 结论互相印证。

## 五、D5 截图取证规则：截图仅作线索，关键值必须 SQL 复核

**通用化表述**：远程方回传的截图小字（相似数字、长流水 ID、相邻行配置）易误读，**仅作线索**；关键列值的归属必须让远程方用 SQL 精确复核（SELECT 指定主键/业务键回传文本结果）后再定论。禁止仅凭截图下排查结论——一次误读会把整个排查方向带偏，且错误定性往往数轮后才被发现。

**本次实例**：远程方截图显示某配置行"疑似命中目标产品码"，但行内小字归属字段经 SQL 精确复核后确认归属另一业务线——若凭截图定论将把排查引向"配置错误"的错误方向（正是 SQL-2 归属确认步骤存在的原因）。

## 六、D6 修复模式三件套

定性完成后，修复按三件套执行，缺一不可。

### a) 等同判断升级为业务语义级

**通用化表述**：行号/机构号/ID 的 equals 比较判业务"等同"时，必须按业务口径选择真实粒度——跨业务环节复用的字段（如交易要素中的对手方字段来自前手环节），字段值可能来自其他环节，**编码相等 ≠ 业务等同**。粒度按业务口径选择：法人级 / 机构级 / 行号级，并在注释中说明"为什么选该粒度"。

**本次实例**：原判定"承兑行行号==贴现行行号"——转贴现买入时贴现行字段=上手外行，他行承兑+他行贴现且两行号恰相等的票被误判自承自贴。修复：改为法人级判定（查机构表按 BANK_NO+LEGAL_NO 关联比对法人号）。

### b) 静默跳过必须补留痕日志

**通用化表述**：钩子跳过分支打 info 日志，内容必须含**判定依据的关键上下文**（参与判定的字段值 + 判定结论），保证后续同类反馈可直接从日志定位卡点，不再依赖排除法逐层缩小。

**本次实例**：跳过占用时 info 输出判定依据（承兑行行号+法人号+票号），内网同类反馈可直接从日志定位，无需再走 SQL 判别集全程。

### c) fail-open / fail-close 决策论证

**通用化表述**：钩子依赖的查询/服务抛异常时，放行还是拦截必须论证，禁止默认放行或默认拦截：

```
钩子依赖的查询/服务抛异常，钩子应放行还是拦截？
├─ 下游有兜底保护（如额度不足由 service 层抛业务错误）
│    → fail-open 可选：放行主链路，由下游兜底拦截，异常 error 留痕
└─ 下游无兜底保护
     → fail-close：拦截业务（保守方向），异常 error 留痕
     → 或直接中断业务并给出明确错误提示
无论选哪种：异常必须 error 留痕 + 注释论证选择依据（兜底点写明）
```

**保守方向判据**：fail-open 是否可接受取决于"该错误是否可被下游兜底保护"——可兜底 → fail-open 不扩大风险；不可兜底 → 必须 fail-close。

**本次实例**：查机构表异常按 fail-open 放行占用链路——论证：额度不足由 service 层抛"可用额度不足"兜底，fail-open 不会造成超额放行；若不放行则机构查询抖动会阻断正常占用业务。注释中写明兜底点。

## 七、D7 环境隔离：远程环境独立取证

**通用化表述**：远程环境（内网/生产）独立取证，禁止把本机环境结论（配置值/数据分布/复现结果）直接套用远程环境。本机验证通过的配置组合不代表远程环境同样具备；本机无法复现不代表远程不存在——两个方向的套用都禁止。

**本次实例**：本机环境无法复现"额度未占用"（本机与远程配置分布不同），定性结论完全以远程方回传的 SQL 判别集结果为准，本机复现失败不作为排除依据。

## 八、验证等级

| 变更类型 | 最低验证等级 |
|:---|:---|
| 补留痕日志 | 编译通过 + 回读代码确认日志含判定依据关键上下文（字段值非空拼接） |
| 等同判断粒度改造 | 编译通过 + 单测覆盖"编码相等但粒度不等同"边界用例（如同行号不同法人） |
| fail-open/fail-close 决策 | 注释论证 + 下游兜底路径可达确认（代码走查或异常注入验证兜底真实触发） |
| 远程环境定性 | SQL 判别集逐条回传 + 每条判读结论落档（截图线索须经 SQL 复核后才可引用） |
