# BEMP 测试用例编写方法论

## 五步工作流

```
① 功能地图 → ② 优先级矩阵 → ③ P0用例设计 → ④ 案例集扩展 → ⑤ 测试数据准备
```

### 第一步：网站功能地图制作

**输入**：目标网站地址（`config/generator-config.json` → `target.base_url`）

**方法**：通过 Playwright MCP 自动探索
1. 启动浏览器，访问目标地址
2. 登录系统（复用 bemp-webapp-testing 的 LoginManager）
3. 遍历主菜单 + 子菜单，记录页面路由
4. 每个页面：截图 + 提取关键元素（选择器/功能）
5. 记录页面间跳转关系和状态流转

**输出**：`references/website-functional-map.md`（按 `assets/templates/functional-map.md` 模板）

### 第二步：测试范围与优先级矩阵构建

**输入**：网站功能地图

**方法**：基于功能地图进行系统性分析
1. 核心流程识别：确定用户必用且对项目至关重要的功能模块
2. 风险点评估：识别高风险区域（输入边界、状态改变、权限校验等）
3. 按优先级矩阵模板生成

**输出**：`references/test-priority-matrix.md`（按 `assets/templates/priority-matrix.md` 模板）

**优先级定义**（见 `config/generator-config.json` → `priority`）：

| 优先级 | 含义 | 测试策略 |
|:---|:---|:---|
| P0 | 核心资金流程 | 全量测试，覆盖所有边界和异常 |
| P1 | 核心业务流程 | 主流程 + 关键异常分支 |
| P2 | 辅助功能 | 常规测试主流程和常见异常 |
| P3 | 管理类功能 | 基础功能验证 |

### 第三步：P0 级别功能用例设计

**输入**：测试范围与优先级矩阵（P0 行）

**方法**：针对 P0 级别功能进行详细用例设计
1. 业务流程：至少1个完整正常流程 + 1个典型异常流程
2. 边界测试：最大/最小输入值、空值、特殊符号
3. 用户体验：模拟真实用户操作习惯

**输出**：`test-cases/{子系统}/{模块}.md`（按 `assets/templates/test-case-P0.md` 模板）

**用例编号规则**：`TC-{模块缩写}-{三位序号}`（缩写见 `config/generator-config.json` → `case_id_prefixes`）

### 第四步：测试案例集扩展

**输入**：P0 用例集 + 系统整体理解

**方法**：
1. 需求影响性分析：评估用户输入需求对系统各模块的潜在影响
2. 案例集补充：扩展测试案例以覆盖潜在影响区域
3. 场景覆盖增强：添加边缘场景、并发场景等特殊测试案例

**输出**：补充用例追加到对应模块 MD 文件

### 第五步：测试数据准备

**输入**：完整测试用例集

**方法**：通过 Oracle MCP / MySQL MCP 查询数据库
1. 读取用例文件，提取数据需求
2. 查询现有数据，识别缺口
3. 生成补充 SQL 并执行
4. 验证数据就绪

**输出**：`test-data/{模块}-test-data.md`（按 `assets/templates/test-data.md` 模板）

## 用例结构规范

每个测试用例必须包含：

| 字段 | 说明 |
|:---|:---|
| 用例编号 | TC-{模块缩写}-{序号} |
| 用例名称 | 简明描述测试内容 |
| 优先级 | P0/P1/P2/P3 |
| 所属模块 | 模块名称 |
| 前置条件 | 服务状态 + 登录 + 数据 |
| 测试步骤 | 操作 + 预期结果表格 |
| 验证点 | 功能 + 个性化路径 + 控制台错误 |
| 测试数据 | 字段/值/说明表格 |

## BEMP 特有验证点

1. **个性化路径**：API 请求使用当前银行 `url_prefix` 前缀
2. **组件覆盖**：个性化组件正确覆盖产品化组件
3. **控制台错误**：无 TypeError/ReferenceError/ChunkLoadError
4. **数据隔离**：查询结果仅包含本机构及下级机构数据
5. **弹窗关闭**：X按钮/关闭按钮/重置按钮三通道验证
