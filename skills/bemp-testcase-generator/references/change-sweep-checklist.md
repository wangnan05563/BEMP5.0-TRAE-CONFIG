# 变更影响清扫清单（用例套件矛盾断言检测）

> 对应复盘模式：_shared/test-workflow-retrospective.md **P20**（失败点 W12-05）
> 触发时机：用例修订/作废/功能下线/规则翻转类变更**落盘之后**、提交评审之前
> 核心原则：清扫范围=全量用例文档（含存量套件），非仅本次增量文档——复用优先策略下旧断言散落在存量文档中

## 一、清扫三步法

### S1 变更关键词提取

从本次变更中提取检索关键词清单（写入清扫记录，供复现）：

| 关键词类型 | 示例来源 | 说明 |
|-----------|---------|------|
| 功能名/页面名 | PRD 功能点清单 | 中文全称+常见简称 |
| 按钮/入口名 | 被下线/新增的页面元素 | 如"手动抽取文件"按钮 |
| 接口路径/方法名 | 被删除/新增的 Controller 映射 | func_xxx / REST 路径 |
| 参数键/配置键 | 变更的参数/开关 | 参数 key 原文 |
| 用例编号 | 本次修订/作废的编号 | 检查编号级残留引用 |

### S2 全量检索与残留三分类

对上述关键词在用例文档目录（含 test-index.json）执行 Grep（注意 rg 参数误用陷阱 W11-01），命中项按三类处置：

| 残留类型 | 特征 | 处置 |
|---------|------|------|
| ①存在性断言反转 | 同套件内对同一对象方向相反的断言（旧"按钮可用" vs 新"按钮不存在"） | **必须修**：按需求文档当前版本裁决方向，修订旧断言；否则同套件执行结果自相矛盾 |
| ②过时测试假设 | 前置/假设中"实现不具备某能力"的声明，已被新实现推翻（如"后端无独立校验覆盖"） | **必须修**：删除过时假设，预期改为新实现的实际行为（附代码锚点） |
| ③描述性旧口径 | 功能地图/优先级矩阵/数据准备文档中的描述性文字（非执行断言） | 如实申报不越界修改：列入交付物"已知问题"或单独同步任务；不阻塞测试执行 |

### S3 统计联动核对

- 修订/作废用例所在文档的**统计表行**（变更类型列）与**合计行**重算闭合
- test-index.json：对应条目 version/description/case_count 更新，且执行 **P21 summary 闭合校验**（summary 各项 = 条目聚合值）
- 作废用例：确认编号级无残留引用（其他文档/索引是否仍引用该编号），作废声明含"承接关系"（旧用例由哪些新用例承载覆盖）

## 二、清扫记录模板（追加到变更说明或评审提交物）

```
### 变更影响清扫记录（P20）
- 变更类型：{功能下线/口径变更/规则翻转}
- 检索关键词：{关键词1, 关键词2, ...}
- 扫描范围：{用例目录清单} + test-index.json
- 命中与处置：①类 {n} 项（已修：用例号清单）；②类 {n} 项（已修）；③类 {n} 项（申报：文档+位置）
- 统计联动：{文档统计表/索引是否已闭合}
```

## 三、判断边界

- **执行清扫**：功能下线、校验规则翻转、文案/口径变更、用例作废——凡"旧断言可能失效"的变更
- **可跳过**：纯新增功能用例（无旧断言可失效）；一次性独立用例文档（无跨文档引用）；但清扫记录中需注明"本次为纯新增，未执行清扫"以免误判遗漏
