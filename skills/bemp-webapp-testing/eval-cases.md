## 评测用例

### E1 模糊指令启动（对应规约 T3 最小信息启动）
- 触发输入：「测一下机构管理」
- 通过标准：单轮进入执行——银行/账号/端口全部走配置解析链默认值，不追问用户；仅在配置解析失败（doctor-config FAIL）时以一句话+选项澄清；首轮输出为预检摘要，不复述技能能力或执行计划
- 失败标准：先输出冗长计划复述再动手；或反问银行、账号等可从配置解析的参数
- 验证方式：对话推演（无需实机，BLOCKED 可接受，但澄清行为必须合规）

### E2 多银行切换与配置读取粒度（对应规约 T1/T2）
- 触发输入：「--bank huisbank 执行 all 用例」
- 通过标准：取参使用 `load_config.py --file ... --get banks.huisbank.<key>` 单键解析；未整读 test_config.json 全文、未读取 test_config.schema.json（除非显式 --validate-only）；全程未把 ${ENV:XXX} 占位符字面量当参数值使用
- 失败标准：整读配置文件；读取 schema；或用占位符字面量当值
- 验证方式：对话推演 + 实机执行时审计工具调用记录

### E3 工具切换移交（对应规约 T8）
- 触发输入：构造 HUI h-select 包裹 input 导致 Playwright fill 失败的用例场景
- 通过标准：标记 TOOL_SWITCH_REQUIRED 后，移交信息仅含 YAML 用例文件路径+用例ID+失败步骤号+推荐模式四要素，未复制用例全文或页面快照
- 失败标准：移交时粘贴用例 YAML 全文或大段 snapshot
- 验证方式：对话推演

### E4 预检三连与中断策略（对应规约 T5/T6 + 预检三连章节）
- 触发输入：服务未启动状态下执行测试
- 通过标准：预检合并为 health_check.py 单次调用（端口+配置校验一次完成），数据就绪检查紧随其后；等待逻辑由脚本内置完成，对话中无逐次 netstat 轮询输出（≤1 次）；预检摘要 ≤20 行；仅 BLOCKED 时打断用户并附修复建议
- 失败标准：对话内手写循环 netstat（>1 次轮询输出）；预检通过前逐用例请示
- 验证方式：实机（停服务后执行 health_check.py 观察输出行数与结构）

### E5 报告回传格式（对应规约 T7 + 报告模板摘要区）
- 触发输入：完成一轮多用例测试后生成报告
- 通过标准：对话内仅回传报告「对话回传摘要区」表格（每用例一行：ID/状态/失败分类/证据路径）+ BLOCKED 清单；报告全文、控制台日志、诊断明细均落盘 aotutests-playwright/ 并以文件路径引用；失败诊断遵循 [DIAGNOSIS] 模板且日志全文以路径引用
- 失败标准：对话中粘贴报告全文、控制台日志原文或逐用例长篇过程叙述
- 验证方式：实机执行后对照对话输出与报告文件

### E6 L3 桌面兜底（对应「L3 桌面兜底」章节）
- 触发输入：导出功能触发系统"另存为"对话框，Playwright 与 Chrome DevTools 均无法定位该对话框元素
- 通过标准：先懒加载读取 `references/computer-use-guide.md`（未整读、按索引命中章节）；接入参数经 `config/computer-use.json` 单键解析（未使用占位符字面量）；动作串行且每步复验；截图归档后回到 Playwright/数据库二次验证业务结果再回填用例
- 失败标准：未读手册直接操作 computer-use；用 computer-use 处理 DOM 可解场景或替代 DOM 断言；未复验即标记 PASS；在非测试环境执行
- 验证方式：对话推演 + 实机（可选，需桌面会话）
