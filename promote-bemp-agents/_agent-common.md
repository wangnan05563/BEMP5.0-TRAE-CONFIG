# BEMP 智能体通用规范（共享层）

> 本文件为 9 个 BEMP 智能体的共享上下文，沉淀通用流程、交接声明、禁止事项、降级原则、银行配置切换等跨智能体通用内容。各智能体提示词仅保留专属逻辑，通用部分引用本文件。
>
> **引用方式**：各智能体在文件头部增加一行 `> 通用规范详见 [_agent-common.md](./_agent-common.md)`，并在对应章节以"详见 _agent-common.md §X"引用。

## 1. 通用流程铁律

> 详见 `rules/bemprule.md`，以下为智能体执行层面的核心约束摘要。

1. **流程闭环**：流程必须走到"输出交付文档"，不得中途结束
2. **阶段推进**：每阶段完成→输出交接声明→立即执行下一阶段，禁止等待用户确认
3. **智能体调用**：所有阶段任务必须通过 Task 工具调用对应智能体，禁止在主对话中直接执行技能任务
4. **降级原则**：MCP 不可用时，智能体应输出降级方案而非跳过智能体
5. **前置检查**：任一前置检查失败 → 输出修复建议，不得跳过智能体

## 2. 阶段交接声明标准模板

每阶段完成后必须输出交接声明，格式如下：

```
## 阶段交接声明
- 当前阶段：[阶段名称] ✅ 已完成
- 下一阶段：[阶段名称]
- 下一阶段智能体：[智能体名称]
- 下一阶段技能：[技能名称]
- 交接上下文：[传递给下一阶段的关键信息摘要]
```

**并行阶段**：当下一阶段与当前阶段无依赖（‖ 标记）时，交接声明中注明"并行执行"，并使用 `run_in_background: true` 异步启动。

## 3. 银行配置切换原则

BEMP 项目支持多银行个性化，所有智能体和技能遵循统一切换机制：

| 切换方式 | 说明 | 优先级 |
|---------|------|--------|
| `--bank <银行代码>` 命令行参数 | 显式指定银行 | 高 |
| `active_bank` 配置项 | test_config.json 中的默认银行 | 中 |
| 自动检测 | 根据路径 banks/ext-<银行代码> 推断 | 低 |

**银行配置文件**：`config/banks/<银行代码>.json`，包含 URL 前缀、登录账号、路由、chartTools 等银行级覆盖配置。

**配置继承**：技能级（默认）→ 项目级（覆盖）→ 银行级（覆盖），deep-merge 策略。

## 4. 降级处理原则

| 场景 | 降级方案 |
|------|---------|
| SonarQube MCP 不可用 | 使用 sonar-scanner 命令行工具 |
| SonarQube 服务未启动 | 启动服务后重新扫描 |
| Token 无效 | 提示用户配置后重新扫描 |
| Playwright MCP 不可用 | 降级为 Python+Playwright 脚本 或 代码审查 |
| Chrome DevTools MCP 不可用 | 降级为代码审查 + 后端 API 验证 |
| Oracle/MySQL MCP 不可用 | 降级为 sqlplus/mysql 命令行 |
| 数据库远程不可达 | 通过后端 API 间接验证数据库状态 |
| 图表生成工具降级 | drawio→mcp→graphviz→antv→matplotlib→占位文字（5级降级链，详见 chart-tools.json） |

**降级输出要求**：降级发生时，智能体必须在交接声明和最终报告中明确标注降级方案、降级原因、对验证深度的影响。

## 5. 回退规则

| 发现阶段 | 回退到 | 触发条件 |
|---------|--------|---------|
| 代码开发 | 方案设计 | 需求理解偏差致方案不可行 |
| 代码评审 | 代码开发 | 评审发现架构/规范问题 |
| 功能测试 | 代码开发 | 测试发现功能性缺陷 |
| 功能测试 | 测试用例编制 | 用例覆盖不足 |
| 二轮调试 | 代码开发 | 缺陷根因在代码层面 |
| 代码质量扫描 | 代码评审修复 | 扫描发现严重问题需修复 |

**回退约束**：同一阶段最多回退 3 次，超限暂停与用户确认；回退原因和影响范围须在交接声明中注明。

## 6. 缺陷分派原则

| 缺陷类型 | 修复 | 验证 |
|---------|------|------|
| 前端/后端缺陷 | bemp-personalized-developer | bemp-auto-tester 或 chrome-devtools-debugger |
| 测试数据/配置问题 | bemp-implementation-engineer | bemp-auto-tester |

**闭环要求**：修复→验证双重确认才算关闭，验证与修复不能同角色；P0/P1 修复后必须回归验证。

## 7. 门禁速查

| 门禁 | 通过条件 | 不通过处理 |
|------|---------|-----------|
| 需求确认 | 无阻塞项 或 阻塞项不涉核心流程 | 阻塞核心→等待确认；可假设→标"测试假设" |
| 用例评审 | 严重=0 且 主要=0 | 严重>0→回退用例编制；主要>0→执行前修复 |
| 缺陷闭环 | P0/P1 全部修复验证通过 | P2/P3 记录"已知问题"，交付文档中列出 |
| 代码评审修复 | 修复后原评审智能体验证通过 | 不通过→重新修复，不得跳过验证 |
| 代码质量扫描 | SonarQube 服务可用 + Token 有效 + 扫描结果上传成功 | 服务不可用→启动服务；Token无效→提示配置；结果未上传→重新扫描 |

## 8. 输出目录规范

所有自动化测试生成的文件、报告、资源统一存放于项目根 `aotutests-devtools/` 目录：

| 子目录 | 用途 |
|--------|------|
| `aotutests-devtools/testcases/<需求名>/` | 测试用例文件 |
| `aotutests-devtools/testreports/<需求名>/` | 测试报告文件 |
| `aotutests-devtools/testdata/<需求名>/` | 测试数据文件 |
| `aotutests-devtools/delivery/<需求名>/` | 交付文档 |
| `aotutests-devtools/index.json` | 生成内容元数据索引 |

**文件命名规范**：`<需求名>-<文档类型>-v<版本号>.<扩展名>`，便于识别和追溯。

## 9. 智能体专属逻辑边界

各智能体提示词仅保留以下专属内容，通用内容引用本文件：
- 角色定位（本智能体是谁）
- 技能绑定（调用哪些技能）
- 工作流程（本阶段专属步骤）
- 专属禁止事项（本智能体特有）
- 阶段交接（本阶段的下一阶段）
- 英文标识名、调用时机、示例

**禁止重复**：通用流程、交接声明模板、银行配置、降级原则、回退规则、缺陷分派、门禁速查、输出目录规范等内容不得在各智能体中重复定义，统一引用本文件。
